## Engine floors and exposure

- The repository requires Node 22.22.2 or its supported newer lines. Happy DOM 21 requires Node 20 or newer; Vitest 5.0.3 requires Node 22.12 or a supported newer line. Both are development dependencies. Foldkit's published Node 20.19 floor is unchanged.
- MCP SDK 1.32 requires Node 18; the selected Hono adapter requires Node 20. Both fit DevTools MCP's published Node 22.19 floor. body-parser requires Node 18; ip-address requires Node 12. Zod and fast-uri declare no higher Node floor.
- Undici 8.12.3 requires Node 22.19, below jsdom 30's existing Node 22.22.2 floor. This change does not raise another published runtime's engine floor.
- The Website ships Monaco's sanitizer code. Its current sanitizer accepts strings, uses normal trusted-HTML or fragment output, and does not enable `SAFE_FOR_TEMPLATES`, `IN_PLACE`, or XHTML parsing. The reviewed critical shadow-root precondition was not established in this call path. The dependency was patched regardless.
- DevTools MCP uses low-level `Server` with `StdioServerTransport` in `src/server.ts`, and `ws` for its relay client. It does not start the SDK's HTTP, OAuth bearer-authentication, experimental task, Express, or static-file server paths. The SDK's HTTP validation advisory explicitly excludes stdio-only servers and additionally requires opt-in limits for affected HTTP deployments. Zod parsing still occurs on the stdio request path; the SDK and its installed graph were updated rather than waived wholesale.
- Happy DOM 21 [disables iframe and CSS fetching by default](https://github.com/capricorn86/happy-dom/releases/tag/v21.0.0). The lead corrected two tests that deliberately need iframe realms by providing empty `srcdoc`. No global network-loading option was restored.

## Remaining findings

**Minimatch 10.2.6, [GHSA-g3hv-75wg-m249](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249):** patched in 11.0.1. The latest inspected TypeDoc 0.28.20 and typescript-estree 8.72.1 still require 10.x. The old matcher is reached by TypeDoc's fixed repository entrypoints, Madge's repository TypeScript analysis, and the examples e2e ESLint configuration's checked-in file/ignore globs. No application request supplies these patterns. Source and configuration from a pull request remain untrusted CI inputs; this finding is not waived merely because the tools run in development. Minimatch 11 changes the matching implementation and public methods, while TypeDoc uses matcher internals such as `matchOne`. Forcing 11 across these parents is not a compatible security patch.

**Glob 13.0.6, [GHSA-3g3m-2fjr-6pw4](https://github.com/isaacs/node-glob/security/advisories/GHSA-3g3m-2fjr-6pw4):** patched in 14.0.2. Latest inspected rimraf 6.1.3 still requires `glob ^13.0.3`. This graph is now build-only in all nine workspace owners. Their `clean` scripts pass local paths such as `dist` and `*.tsbuildinfo`; they do not supply a glob traversal AbortSignal or depend on its timeout stopping work. The reported cancellation-bypass precondition is not present in that path. Removing rimraf from the CLI's production dependencies also removes this path from ordinary scaffold installation. The workspace advisory remains open pending a compatible parent release or a separately reviewed cleanup-tool replacement.

Neither finding has been hidden through an audit exclusion. Shipping with these remaining workspace findings is a separate release decision.
