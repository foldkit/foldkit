# Active Website snippets

Run from the isolated repository root:

```sh
node internal/layered-constructor/website-snippets/verify.mjs
```

The verifier checks 129 self-contained snippet roots against the built public packages, then runs nine existing or focused Story/Scene examples. It emits and relocates a consumer of `Html.MessageOf<Builder>` using physical copies of the built Foldkit and UI packages, with `skipLibCheck: false`. Two copied-declaration controls must fail when the helper loses or widens its Message union; restored declarations must pass. Canonical packages are not mutated.

The helper proof preserves a local Number payload and generated child delivery. The selected snippets cover independent contracts, extracted builders, Layer-provided children, genuine Schema-generic families, operation policies, keyed and variant storage, Command Services, Mounts, Subscriptions, Query/KeyedQuery, and scoped tests.

`selected.json` records exactly which complete files compile. The Website normally excludes all snippets from its typecheck: other snippets are partial excerpts, multiple labeled files, intentional rejected examples, historical code, or comparisons with other frameworks. The verifier audits all 525 active TypeScript files for superseded completion APIs; this audit is not a claim that every excerpt independently compiles.

The 31 published-release or migration “before” files retain their original hashes. Active “bad” examples retain their teaching error while unrelated authoring boilerplate follows the current API. `blockStepBranchesBefore.ts` and `updateConnectedStepBefore.ts` are active incorrect/correct comparisons on the Block and update pages, rather than historical migration examples. `original-hashes.json` records the pre-migration snapshot.

Selected behavior checks run handlers synchronously through Story/Scene without executing handler Layers. The owning Pins implementation tests its private Subscription registry; the parent’s headless Story uses generated Binding delivery. Dialog Mount acquisition follows normal element creation and original Definition identity. No browser network requests run.

Verification artifacts use fresh `verification-*` directories. `verification-pnMheq/results.json` preserves the first complete passing run. `verification-wHGoqq/results.json` also includes the alternate-view customization root and passes against the corrected viewless Binding bridge, including declaration controls. After the child `blocks/` layout and named UI subpath import migration, `verification-JJDw6v/results.json` passes all checks, including source-free declaration controls. `verification-qpgvc2/results.json` verifies root UI namespaces, immutable Story comparisons and final Model results, including both declaration controls. The verifier links its existing UI and Vitest dependencies locally so it also runs in a fresh worktree without incidental root dependencies. This is documentation and public-type verification, not a compiler or rendering benchmark.
