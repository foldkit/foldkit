## Next-preview priorities

The [next-preview task list](./next-preview-tasks.md) tracks implementation, assessment, verification, and release work.

Start with [the workspace application and scale workloads, #1767](https://github.com/foldkit/foldkit/issues/1767). Use its vertical slice to assess ownership and coordination, then measure larger static compositions through the existing performance infrastructure. Reproduce the [MyRemotely migration findings](https://github.com/foldkit/foldkit/pull/1655#issuecomment-6325362294) against the latest published preview before classifying a reported gap as missing functionality.

Bookmarked consumer-friction checks:

- [x] Identity-based captured argument projection through `Story.Command.argsOf` and `Scene.Command.argsOf`, including qualified child Commands, exact args, foreign same-name rejection, and explicit occurrence selection. [Contract and verification](pending-command-inspection.md).
- [x] Shared view helpers that accept Mount-bearing Attributes without losing requirements or registration evidence. Two real Dialog owners now have source/emitted/relocated positive and negative fixtures and copyable guidance for the existing caller-owned renderer pattern. [Scope and limits](./workspace-consumer-friction.md#shared-mount-bearing-rendering).
- [x] Safe child reset and initialization guidance, including retained Commands and registered Binding use. Counter/parent snippets distinguish Message-backed reset from baseline initialization; no fresh-generation or cancellation claim. [Scope and limits](./workspace-consumer-friction.md#required-child-reset).
- [x] Improve reported assembly diagnostics with accepted/rejected source and relocated-declaration assertions. The new map helper is recognized by ownership lint through import provenance, including function-reference HashMap transformations. [Current outcomes and boundaries](composition-feedback-closeout.md).

Foldkit's beta migration contract permits breaking changes without an incremental compatibility path. The supported migration approach is agent-assisted, with accurate guides, copyable prompts, and verified application migrations. Codemods and a compatibility bridge are outside this plan. A large diagnostic count alone does not justify retaining the previous architecture; incorrect diagnostics, unclear contracts, and unnecessary wiring are actionable findings.

Record/HashMap adapters (#1706), aggregate ManagedResource Layers (#1759), public pending-Command projection, and focused diagnostics are implemented locally for this preview. [Integrated closeout](composition-feedback-closeout.md). Exact whole-variant storage is now supported by opt-in `makeVariantBinding`, with Auth's two eligible Bindings migrated. Nested or wrapped variants retain general accessors. [Scope, compiler cost and safety proofs](variant-binding-assessment.md).
