# Bundle reachability investigation: 2026-11-07

## Decision

The exact current-source attribution gate passes. A properly isolated no-map
rebuild and its hidden-map twin are both byte-identical to the retained
published artifact: 475,519 raw bytes, 147,123 whole-asset gzip bytes, and
SHA-256 `445b31212df9efe25ce6e81fe60cb7a5dfc583c46fc098dd84de40e234e9d146`.

Disjoint source-map spans attribute 128,187 raw bytes, 26.96% of the artifact,
to Block authoring and completion modules. That is substantial enough to
justify a future bounded physical-specialization experiment, but it is not a
claim that all 128,187 bytes are removable and it does not justify an API
migration. The smallest credible target is the approximately 23,769 raw bytes
in the contracted/constructed/hybrid generic bridge, where `Block.make`
currently enters a generic Definition/Contract Runtime and removes fields only
after constructing the escaping object. The specialized entry must retain the
same checked native Composition and assembly path.

Do not start that prototype in this investigation. The existing HTML-definition
work in PR #1585 and optional hydration/DevTools boundaries in PR #1581 have
stronger measured precedent and lower architectural risk. Rebase and measure
those first, then recheck whether the Block bucket and generic bridge remain
material.

No Foldkit source, public API, benchmark behavior, test, browser state, commit,
or remote was changed. All builds used copies under
`/private/tmp/foldkit-bundle-reachability-20261107`; the frozen source,
artifacts, and receipts under
`/private/tmp/foldkit-mount-iterative-20261107-32wcjI` remain untouched.

## Current-source reachability and removability inference

This section explains the exact mapped retention; it does not treat every
mapped byte as removable.

The benchmark creates one root Block with no child occurrence or Mount. The
reachable constructor chain is nevertheless:

1. `internal/lustre-benchmark/src/application.ts` calls `Block.make`.
2. `experimental/contracted/unified.ts:650` snapshots the declaration and
   calls `makeDefinitionRuntime`.
3. `experimental/contracted/runtime.ts:599` creates the full contracted
   descriptor and public authoring/completion object.
4. `experimental/constructed/runtime.ts:735` creates the constructed
   Definition and, at line 773, calls native `makeDefinition`.
5. Completion constructs a native Composition at line 536 and assembles its
   prepared Block at lines 595–596.
6. `experimental/contracted/unified.ts:683-684` deletes only `contract` and
   `makeBlock` from the escaping object after the object has already been
   constructed.

The escaping Block object and its Composition retain authoring and completion
capabilities, including `makeComposition`, `prepareBlock`, `makeLayer`,
Binding constructors, OutMessage policy helpers, operations, InMessage
adapters, subscription and ManagedResource helpers, graph ownership checks,
and assembly validation. Object spread, `Object.assign`, reflection, and the
escaping object identity prevent the bundler from proving those properties
dead. `makeLayer` also retains both record and Effect-constructor branches.

The native `makeDefinition` path concretely constructs `makeView`, `makeInit`,
`makeUpdate`, `makeStep`, `makeOutMessageFold`, `makeOutMessageForward`,
`makeFieldsStep`, `makeNoopStep`, `makeCommandsStep`, `makeSubscriptions`, and
`makeManagedResources`, then creates `makeBindChild`, `makeMapBinding`, and the
full Binding constructor record. The exact map shows the consequences in
`bindChild.ts`, `delivery.ts`, `definition.ts`, Binding connection modules,
and the contracted/constructed bridge even though this fixture has no child
occurrence or Mount.

The correct removability proof is not “the fixture does not call these
methods.” A future physical specialization must show that the specialized
entry never constructs or returns the full authoring object, while still using
the existing checked Composition/assembly path and preserving ownership,
Schema, graph, acquisition, passivity, and runtime validation. The proof must
include exact asset equivalence controls and the existing graph/assembly
tests; dropping validation is not an acceptable optimization.

A removability experiment succeeds only if a physically distinct Block entry
never imports or constructs the generic Contract/Definition bridge, the
hidden-map twin has no spans from the targeted modules, and the emitted raw
delta equals the disappeared disjoint spans after accounting for minifier
changes. It must also pass the existing ownership, Schema, graph,
extractability, passivity, acquisition, and assembly checks. Merely not calling
a property in the benchmark, or deleting it after object construction, is not
proof.

Earlier candidate source-map work attributed 78,566 generated raw bytes to
Block machinery, 15,749 to Runtime, 14,791 to other Foldkit, and 4,500 to
Effect/dependencies. Those are useful older-candidate leads only. They are not
current counts, use different bucket boundaries, and were not subtracted from
the current asset. The exact 475,519-byte attribution above supersedes them for
this recommendation.

## Open performance PR applicability

### PR #1581: optional hydration/DevTools and consumer-size profiler

Commit `43f844cf744989a347a30c1ba7d7fee1a65949f2` is based on
`9d701af6a75161962a9600422743d7531c0e4828`, which is also the merge base of
the current published commit.

What remains applicable and is missing now:

- Current `runtime/runtime.ts` directly imports `makeDevToolsIntegration` and
  `resolveHydrationHandoff`; `runtime/renderer.ts` directly imports
  `__hydrateVNode`. Fresh production boots therefore still expose the same
  retention mechanism the PR was designed to remove.
- The PR's registration boundary supplies a small live-only DevTools
  integration by default and has the optional DevTools host register recording.
- The PR moves hydration adoption and handoff into the `hydrate` startup path,
  so `run` does not retain them.
- `internal/bundle-size` and its published-export-map, no-source-alias fixtures
  do not exist on the current branch. That profiler is directly useful for
  preventing another evidence gap.

Historical evidence from the commit message reports the counter falling from
about 95 KB to 86 KB gzip while its hydrated and recording fixtures retain the
optional capabilities. This is not a current-commit delta, but the exact map
shows the same current retention leads: `hydrate.ts` is 8,697 raw bytes,
`runtime/hydrationHandoff.ts` is 7,025, `runtime/devToolsIntegration.ts` is
1,910, and `devTools/store.ts` is 3,599.

The patch is not a safe transplant. Since its October base, Runtime gained the
Block/Layer construction graph, occurrence and resource lifecycles, changed
DevTools dispatch preparation, and substantially changed `runtime.ts`,
`renderer.ts`, `start.ts`, hydration, tests, and the Vite plugin. A three-way
merge reports conflicts in every core implementation file. Port the two
capability boundaries as current-architecture changes, and port the profiler
separately; do not cherry-pick the Runtime implementation wholesale.

## Recommended order and controls

1. For every copied workspace, retarget all local package and plugin links into
   that same copy. Assert that the Vite plugin's resolved Foldkit package root
   contains every aliased Foldkit core source path. This same-runtime,
   same-package-root invariant is required; content hashes alone do not prove
   isolation.
2. Freeze and record exact Node, Vite, Rolldown, native binding, lockfile,
   environment, configuration, source, compiled package inputs, and resolved
   links. Remove the whole output directory before the first build.
3. Require the no-map rebuild to match the chosen baseline by JavaScript
   SHA-256 and byte length. Require a hidden-map twin to emit byte-identical
   JavaScript. Require disjoint interval totals, including unmapped bytes, to
   sum to the exact raw asset. Report gzip only for the whole asset.
4. Port the #1581 published-export-map profiler so these controls and optional
   capability fixtures become durable CI evidence.
5. Isolate #1585's shared HTML definitions against current types and semantics;
   compare no-change and experiment artifacts with counter, hydrated,
   recording, and Typing Game controls.
6. Port #1581's hydration and DevTools boundaries as current Runtime work, with
   the same fresh/hydrated/recording controls.
7. Rerun exact attribution after those lower-risk wins. If the 128,187-byte
   Block bucket and especially the 23,769-byte generic bridge remain material,
   a bounded physical `makeBlockRuntime` specialization is justified. It must
   preserve the public Block API, extractability, passive configuration,
   ownership and Schema checks, graph acquisition checks, and checked native
   Composition/assembly path. Do not promise migration or drop Runtime
   validation from this evidence.
