# Application architecture audit — 2026-11-05

## Scope

Audited active production TypeScript in every example, the Website, Typing Game, and the `create-foldkit-app` templates against the current application conventions. The review covered:

- update, Composition, and shared Step responsibility;
- Message, OutMessage, InMessage, Command, Mount, and transition names;
- parent domain ownership versus child editing and interaction state;
- Query ownership and repeated domain lookup boundaries;
- child initialization and `makeInitIfMissingStep` applicability;
- direct and keyed OutMessage folds;
- Block and barrel organization;
- Schema/type adjacency and logical spacing;
- conditional class construction and root UI imports;
- tuple construction and handler dependency acquisition.

Renderer files and application tests were reviewed and changed by their dedicated owners. This audit did not alter framework APIs, historical content, compiler fixtures, or preview contract records.

## Changes made

- Query Sync now gives the Diet and Period Listboxes exact runtime Value Schemas. `All` is an explicit filter choice instead of an empty-string sentinel, and OutMessage folds no longer decode values that the child contract already validated.
- Job Application's finite pronoun choices now use the existing `PronounOption` Schema in the Listbox contract and parent Model.
- Pixel Art's local grid-size transition is `changeGridSize`, not `requestGridSizeChange`: it either changes local state or prepares the confirmation Dialog rather than asking another owner to perform the whole operation. Its mirror transitions use a constrained `Match` return, and history selection uses Effect Array access.
- Workspace defers the command-palette Dialog close operation through the owning Step instead of materializing a connected Binding operation at module initialization.
- Shopping Cart exposes its static product collection as a `ReadonlyArray`.
- Typing Game's server startup moved from `src/index.ts` to `src/main.ts`; package and Docker entry paths follow it. Shared domain and RPC declarations moved to `src/room.ts`, with `src/index.ts` restored as the stable barrel. Public package names and exports are unchanged.

## Deliberate exceptions and limits

The DevTools host application was included in the final pass. Its scrubber
Binding now mirrors `scrubberSlider`, the Composition factory returns named
fields instead of a tuple, generic section headers are removed, and Message
unwrapping names its selected Block and uses checked property access. Small
renderers take their actual inputs. Its host Runtime adapter and view-identity
cache retain their integration-specific lifetimes; they are not application
workflow state stored in a Command constructor. Its native DOM/runtime tests do
not use the Story or Scene DSL and have no mutable outer captures.

- `Listbox.makeBlock()` remains correct for values that are genuinely unrestricted or generated dynamically, including Job Application graduation years and Pixel Art palette indices. Finite domain choices use explicit Value Schemas.
- Native Selects remain in the Select component's own Website/Showcase demonstrations and the SSR example's hidden parser-equivalence fixture. The latter checks native selected-option behavior before and after hydration; replacing it would erase that regression case. Workspace has no native Select fallback.
- `Binding.init` remains necessary when an operation replaces variant or wrapper storage, resets sibling parent fields, or contributes parent Commands. `makeInitIfMissingStep` is used only for supported direct-value Record/HashMap retention.
- `sync` and `observe` remain in names only where the code actually synchronizes or observes an external imperative resource, notably chart, map, browser, and Mount lifecycles.
- Tuple construction remains only where literal tuple identity is required; ordinary children, bindings, and init arguments use contextual array literals.
- No large domain abstraction was introduced solely to reduce a small local lookup. Existing domain namespaces and barrels are used where they own a meaningful query.
