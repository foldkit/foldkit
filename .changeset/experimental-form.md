Add experimental Form, a viewless Submodel for form state. It keeps each field's input, errors, and interaction state, and returns the Commands that validate and submit it. Import it from `foldkit/experimental` or `foldkit/experimental/form`.

Define each field with an Effect Schema, an initial input, optional `rules`, an optional async `validate` Effect, and `validateOn: 'Change' | 'Blur'`. A field stores what the control produces, the Schema's `Encoded` side, so a number field can hold `'12a'` while the person types. The Schema turns the input into the value, and a failure shows as a field error. `initial` and `changed` take inputs. `rules`, `validate`, `execute`, and the overrides passed to `init` and `reinitialize` take values. `validate` runs only after the rules pass, and not for an empty value in a field without a `required` rule. A change or blur shows the first rule that fails, and submitting shows every rule that fails. `fieldView(model, name)` returns a field's input, value, errors, and interaction state.

`Form.define` takes a `name`, used for the Form's Commands, such as `SubmitRegistration` and `ValidateRegistrationEmail`. It throws when two field names differ only in the case of their first letter, because their Commands would share a name. Configure submission with an `execute` Effect, plus optional Schemas for its `data`, its `error`, and a `context` value that isn't a field, such as a record id. `toFieldErrors` shows a typed submission error on the fields it concerns. Services that `validate` and `execute` need become requirements of the Commands Form returns.

The parent stores the Form Model, connects it with `lift`, and renders from its selectors. `lift` requires `foldOutMessage`, which handles the `SucceededSubmit` and `FailedSubmit` OutMessages. A Form inside a Submodel passes the Submodel's OutMessage type to `lift`, returns that OutMessage from `foldOutMessage`, and can forward Form OutMessages with `toParentOutMessage`. The lifted `reset`, `reinitialize(overrides)`, and `submit(context)` return Steps, so they compose with `Update.combine`. Form ignores results from attempts and checks it no longer waits for. Story and Scene tests can match and resolve each Form's `Submit` Command and the `ValidateField.<field>` Command of each field with a `validate` Effect.
