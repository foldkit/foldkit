Validate `assembleBlock` implementations through their channel types instead of a per-candidate composition object. Each `assembleBlock` overload used to build a `Readonly` composition object from its own inferred implementation and validate that object, so the checker ran the local requirement validation once per overload candidate even when every candidate had resolved the same `init`, `update`, lifecycle registrations, `EffectsLayer`, and `hostHandlers`. The validation is now keyed on those channel types, so candidates that resolve the same channels share one cached validation and candidates whose channels are generic defer it. Accepted and rejected programs, the validation error messages, emitted declarations, and runtime behavior are unchanged. The checked-in type-performance ceilings drop from 859,410, 1,609,445, and 386,770 instantiations to 767,670, 1,389,469, and 354,779, the highest counts observed over six runs. On the Website root `ApplicationBlock` member completion with native TypeScript 7.0.2, the checker's instantiation-cache misses fell from 254,263 to 246,357, and the per-candidate composition projection that cost 0.21 s of the instrumented build's 3.7 s cold request is gone.
